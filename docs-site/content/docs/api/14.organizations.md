# Teams and organizations

`createOrganizationsClient()` returns the auth-ai `OrganizationsClient` for the
token already verified by `OidcHttpMiddleware` or `OidcSocketMiddleware`.

```ts
import { createOrganizationsClient } from "ioserver-oidc";

const organizations = createOrganizationsClient({
  config,
  token: request.authToken,
});

const teams = await organizations.listOrganizations({ team: true });
const team = await organizations.create({ name: "Acme Team" });
const invitation = await organizations.createInvitationToken(team.id);
await organizations.join(invitation.token);
```

The token must be minted for the auth-service audience and carry
`organizations:self:manage` (`ORGANIZATION_SELF_SCOPE`). When sign-in is handled
by `@circle-rd/auth-ai`, set `teamManagement: true` on the `AuthClient` so the
scope and auth-service audience are requested.

| Method | Description |
| --- | --- |
| `listOrganizations({ team? })` | User's teams (`true`), companies (`false`) or both |
| `create({ name, logo? })` | Create a domain-less team; auth-service derives the slug |
| `join(token)` | Join a team with its invitation token |
| `leave(id)` | Leave a team; the last owner and companies are refused |
| `createInvitationToken(id)` | Issue a seven-day invitation token |
| `revokeInvitationToken(id)` | Revoke the current invitation token |

The `Organization`, `InvitationToken`, `CreateOrganizationInput` and
`ListOrganizationsOptions` types and the `organizationSchema` /
`invitationTokenSchema` Zod schemas are re-exported. auth-service remains the
decision point; refusals surface as `API_001` with `details.apiCode` set to the
`ORG_*` code.
