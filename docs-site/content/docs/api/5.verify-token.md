# verifyOidcToken

`verifyOidcToken` is the low-level verifier used by both middlewares. Use it in
a background job, a CLI or a custom Fastify plugin.

## Signature

```ts
async function verifyOidcToken(
  token: string,
  config: OidcConfig,
): Promise<OidcUserContext>
```

## Validation

- Signature against the remote JWKS, restricted to an asymmetric algorithm
  allow-list.
- `iss`, `exp`, `nbf`, `aud` and `sub`; `exp`/`iss`/`aud`/`sub` are required.
- `azp` / `client_id` against `appSlug`; mandatory in resource-audience mode.
- The verified `aud` values are copied to `ctx.audiences`.
- ID-token markers (`nonce`, `at_hash`, `c_hash`), non-`access` `token_use` and
  explicit `id+jwt`/`logout+jwt` types are rejected. A required access-token
  `typ` can be configured with `tokenType`.
- `client_credentials` tokens are refused unless `allowMachineTokens: true`,
  for both native and generic providers.

## Errors

Throws a `jose` `JWTVerifyError` (or subclass) on signature/claim failure, and
`OidcTokenError` with code `ERR_MACHINE_TOKEN_FORBIDDEN` for a refused machine
token.

## Example

```ts
import { verifyOidcToken } from "ioserver-oidc";

const ctx = await verifyOidcToken(rawJwt, {
  authServiceUrl: "https://auth.example.com",
  appSlug: "my-app",
  audience: "https://api.example.com",
});

console.log(ctx.sub, ctx.userRole, ctx.plan);
```

## JWKS caching

The verifier keeps an in-process `Map<jwksUri, RemoteJWKSet>`. `jose` handles
key rotation and refetches an unknown key with a cooldown.
