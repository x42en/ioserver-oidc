# OidcSocketMiddleware

`OidcSocketMiddleware` guards a Socket.IO namespace during the handshake.

```ts
server.addService({
  name: "chat",
  service: ChatService,
  middlewares: [OidcSocketMiddleware],
});
```

## Token extraction

The token is read from:

1. `socket.handshake.auth.token` — preferred.
2. `socket.handshake.headers.authorization` — `Bearer <token>` fallback.

```ts
const socket = io("http://localhost:3000/chat", {
  auth: { token: accessToken },
});
```

## Flow

1. Extract the token.
2. Verify it with the same code path as `OidcHttpMiddleware`.
3. Refuse machine tokens unless enabled; allowed machine tokens are not
   auto-provisioned.
4. Provision the local user when the `users` manager exists.
5. Register the connection with `appHandle.session.registerSocket(...)` when the
   session manager exists, and unregister it on disconnect.
6. Inject the same context as the HTTP middleware, including `auth` and
   `authToken`.

## Errors

The connection is rejected with `next(new Error(code))`:

| Code                          | Condition                                  |
| ----------------------------- | ------------------------------------------ |
| `ERR_AUTH_TOKEN_REQUIRED`     | No token found                             |
| `ERR_AUTH_TOKEN_INVALID`      | Signature or claims verification failed    |
| `ERR_MACHINE_TOKEN_FORBIDDEN` | `client_credentials` token on a user route |
| `ERR_OIDC_CONFIG`             | OIDC configuration is unavailable          |
| `ERR_ACCOUNT_DISABLED`        | Local account is disabled                  |
| `ERR_USER_PROVISION_FAILED`   | `users.findOrCreate` or session registration threw |
