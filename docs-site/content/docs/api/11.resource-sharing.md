# Resource sharing

`requireResourceAccess()` is fail-closed: only an explicit `decision: "allow"`
returns. A deny, a timeout or a malformed answer throws `OidcResourceError`
(`ERR_RESOURCE_FORBIDDEN`). Configuration problems throw `ERR_RESOURCE_CONFIG`.

```ts
import { requireResourceAccess } from "ioserver-oidc";

const access = await requireResourceAccess(
  this.appHandle,
  request,
  "gine://project-42",
  { requestId: request.id, source: "api" },
);
```

`subjectId`, `actorClientId` and the audience come from the verified context.
Never take them from a request body. The application asking is the machine
credential of `OidcMachineManager`, not the token's client: the client the user
came through (`azp`) is forwarded as `actorClientId` and only recorded in the
auth-service access log. The allowed decision is also copied to
`request.resourceAccess`.

An allowed decision carries `decisionId` (valid 60 seconds), `expiresAt`, the
effective `permission` (`read` or `write`), and `accessKind`. Ask for the level
the action needs with `permission`; `read` is the default and `write` covers
`read`:

```ts
const access = await requireResourceAccess(
  this.appHandle,
  request,
  "gine://project-42",
  { permission: "write" },
);
```

A user who holds only `read` is refused (`ERR_RESOURCE_FORBIDDEN`). Pass
`access.decisionId` and the request start time to `recordResourceUsage()`:
usage reports no longer carry `subjectId` or `clientId`.

Other helpers:

| Helper | Purpose |
| --- | --- |
| `listAccessibleResources(appHandle, sub, { scheme? })` | Listing filter, never an admission |
| `validateResource(appHandle, id, outcome)` | Validator applications |
| `invalidateResource(appHandle, id, reason)` | Disable a resource whose ownership was lost |
| `recordResourceUsage(appHandle, record)` | Idempotent provider usage report, bound to a `decisionId` |

`recordUsage` rejects conflicting replays with `API_001`/`RES_012`, unknown
resource access with `API_001`/`RES_011` and an invalid or foreign decision with
`API_001`/`RES_016`. `requestId` must be 64 lowercase hex characters.

## Grants for the signed-in user

`createResourceSharingClient()` returns the user's `ResourceSharingClient` from
the token already verified by the OIDC middleware. The token must be minted for
the auth-service audience and carry `resources:self:manage`
(`RESOURCE_SELF_SCOPE`). A bearer token is confined to the application of its
client: it sees and shares only that application's resources.

```ts
import { createResourceSharingClient } from "ioserver-oidc";

const sharing = createResourceSharingClient({
  config,
  token: request.authToken,
});

const grant = await sharing.createGrant(resourceId, {
  subjectType: "user",
  subjectEmail: "colleague@example.com",
  permission: "write",
});
await sharing.updateGrant(resourceId, grant.id, { permission: "read" });
await sharing.revokeGrant(resourceId, grant.id);
await sharing.deleteGrant(resourceId, grant.id);
```

| Method | Purpose |
| --- | --- |
| `createGrant(id, input)` | `permission` is `read` (default) or `write`; subject `user`, `organization` or `application` |
| `updateGrant(id, grantId, { permission })` | Change the level without revoking (`RES_014`, `RES_015`) |
| `revokeGrant(id, grantId)` | End access, keep the row as history |
| `deleteGrant(id, grantId)` | Delete a revoked or expired grant for good (`RES_020` if active) |
| `shareWithApplication(ids, input)` | Share up to 100 resources with one application |
| `listAccessible({ scheme? })` | The user's resources in the calling application, with their level |
| `delete(id)` | Delete a resource for good |

`RESOURCE_PERMISSIONS`, `ResourcePermission` and the `Grant`, `CreateGrantInput`,
`UpdateGrantInput`, `ShareWithApplicationInput` and `BulkShareResult` types are
re-exported. auth-service stays the decision point; refusals carry a `RES_*`
`apiCode` in the auth-ai `API_001` details.
