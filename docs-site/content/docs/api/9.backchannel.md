# Back-channel logout

`registerBackchannelLogout()` mounts the OIDC Back-Channel Logout 1.0 endpoint
on the Fastify instance exposed by `server.getApp()`.

```ts
import { buildConfig, registerBackchannelLogout } from "ioserver-oidc";

registerBackchannelLogout(server.getApp(), {
  config: buildConfig(),
  path: "/auth/backchannel-logout",
  onLogout: async ({ sid, sub }) => {
    await sessions.endBySid(sid, sub);
  },
});
```

## Options

| Option        | Required | Description                                              |
| ------------- | -------- | -------------------------------------------------------- |
| `config`      | Yes*     | Resolved `OidcConfig` used to build the verifier         |
| `auth`        | Yes*     | Existing auth-ai `AuthClient` (alternative to `config`)  |
| `path`        | No       | Route path; default `/auth/backchannel-logout`           |
| `origin`      | No       | Origin used to rebuild the URL; default request Host      |
| `redirectUri` | No       | Callback URI registered in auth-service                  |
| `onLogout`    | Yes      | Called with `{ sid, sub }` for every accepted token       |
| `replayStore` | No       | Shared replay store; memory-only by default              |
| `onError`     | No       | Receives rejected tokens and callback failures           |
| `allowMissingTyp` | No   | Accept a missing logout-token `typ` for a known provider |

\*One of `config` or `auth` is required.

## Validation

The auth-ai SDK validates the logout token signature, `typ`, audience, the
back-channel logout event, the token lifetime, the presence of `sid`, `sub` and
`jti`, and replay protection. The route answers:

| Case                         | Status |
| ---------------------------- | ------ |
| Accepted                     | `200`  |
| Wrong content type / body    | `400`  |
| Invalid or replayed token    | `400`  |
| `onLogout` threw             | `500`  |

Responses carry `Cache-Control: no-store` and no error detail.

Mount the route outside session or CSRF middleware. With several replicas,
provide a shared `ReplayStore`.
