# Migrating to 0.4

`0.4` upgrades `@circle-rd/auth-ai` to `0.4.0` and adds machine API, resource
authorization, signed resource webhooks and RFC 9728 metadata. Existing
middlewares keep their behavior.

## Required changes

1. Upgrade the SDK:
   ```bash
   pnpm add @circle-rd/auth-ai@^0.4.0
   ```
2. If you use a path-based issuer, keep its trailing slash in `OIDC_ISSUER` or
   `AUTH_SERVICE_ISSUER`. It is now compared verbatim to `iss`.
3. Back-channel logout now answers `200` (auth-ai behavior) instead of `204`.
   Update probes and client assertions.
4. A registered but unavailable `OidcConfigManager` now fails at startup
   instead of leaving requests to fail later.

## Optional additions

```ts
server.addManager({ name: "oidcConfig", manager: OidcConfigManager });
server.addManager({ name: "oidcMachine", manager: OidcMachineManager });
```

```env
AUTH_SERVICE_CLIENT_SECRET=<confidential-client-secret>
OIDC_RESOURCE_METADATA_URL=https://api.example.com/.well-known/oauth-protected-resource
OIDC_SCOPES_SUPPORTED=gine:read,gine:write
```

Register webhooks and metadata before `server.start()`:

```ts
registerResourceWebhook(server.getApp(), { secret, onEvent });
registerProtectedResourceMetadata(server.getApp(), { config });
```

Use `requireResourceAccess()` in controllers/services; it fails closed and reads
`sub`, `clientId` and the audience from the verified context. Never pass values
from a request body.

The user-facing `ResourceSharingClient` remains an `@circle-rd/auth-ai` concern:
it needs an `AuthClient` and a `GrantManager` (refresh-token storage), which a
resource-server middleware does not own. Import it directly from auth-ai.
