# Error Handling & Security

## Error codes

### HTTP

| Code                          | Status | Meaning                                       |
| ----------------------------- | ------ | --------------------------------------------- |
| `ERR_AUTH_TOKEN_REQUIRED`     | 401    | Missing or malformed bearer token             |
| `ERR_AUTH_TOKEN_INVALID`      | 401    | Signature or claims verification failed       |
| `ERR_MACHINE_TOKEN_FORBIDDEN` | 403    | `client_credentials` token on a user route    |
| `ERR_ACCOUNT_DISABLED`        | 403    | Local account is disabled                     |
| `ERR_USER_PROVISION_FAILED`   | 500    | `users.findOrCreate` or session registration threw |
| `ERR_OIDC_CONFIG`             | 503    | OIDC configuration is unavailable             |
| `ERR_RESOURCE_FORBIDDEN`      | 403    | Resource admission denied or undecidable      |
| `ERR_RESOURCE_CONFIG`         | 500    | Missing machine manager, subject or audience  |

### Socket.IO

| Code                          | Meaning                                       |
| ----------------------------- | --------------------------------------------- |
| `ERR_AUTH_TOKEN_REQUIRED`     | No token in the handshake                     |
| `ERR_AUTH_TOKEN_INVALID`      | Verification failed                           |
| `ERR_MACHINE_TOKEN_FORBIDDEN` | Machine token on a user namespace             |
| `ERR_ACCOUNT_DISABLED`        | Local account is disabled                     |
| `ERR_USER_PROVISION_FAILED`   | Provisioning failed                           |
| `ERR_OIDC_CONFIG`             | Authentication temporarily unavailable        |
| `ERR_RESOURCE_FORBIDDEN`      | Resource admission denied                     |
| `ERR_RESOURCE_CONFIG`         | Resource helper misconfigured                |
| `ERR_FORBIDDEN`               | Missing an accepted admin role                |

Wallet and gateway helpers use the auth-ai registry (`API_*`, `GW_*`, `CFG_*`).

## Token expiry on long-lived sockets

The token is verified at handshake time. A socket that was accepted stays open
after the token expires. Have the client reconnect with a fresh token before
expiry, or implement a periodic re-authentication event in your service.

## Security guarantees

- Signature verification uses the remote JWKS and an asymmetric allow-list
  (`RS*`, `PS*`, `ES*`, `EdDSA`); `HS*` and `none` are rejected.
- `iss`, `aud`, `exp` and `sub` are required; `aud` values are exposed as `audiences`.
- Resource authorization is fail-closed and uses only verified context values.
- `azp` / `client_id` is bound to the configured client id and mandatory in
  resource-audience mode when a client id is configured.
- Native `client_credentials` tokens are refused by default.
- JWKS keys are cached per URI; `jose` refetches an unknown key with a cooldown.
- Access tokens are never stored by the middleware; they are bounded to 16 KiB
  before parsing.
- Disabled accounts are checked after token verification; a valid token does not
  guarantee access.
- Error responses never include the provider message, the token or a claim
  value.

## HTTPS

Always deploy behind TLS. The generic `oidc` mode trusts the configured issuer
and JWKS URLs, so never build them from a request `Host` header.
