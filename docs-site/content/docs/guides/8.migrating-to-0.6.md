# Migrating to 0.6

`0.6` upgrades `@circle-rd/auth-ai` to `0.6.0` and follows auth-service's
application-scoped resources: an application sees and uses only the resources
it owns or that were shared with it. It needs the matching auth-service release.

## Required changes

1. Upgrade the SDK:
   ```bash
   pnpm add @circle-rd/auth-ai@^0.6.0
   ```
2. `requireResourceAccess()` no longer sends `clientId`. The token's client is
   forwarded as `actorClientId`, for the access log only, and a token without a
   client id is no longer refused. The asking application is the machine
   credential of `OidcMachineManager`.
3. Pass `{ permission: "write" }` when the action changes the resource. `read`
   stays the default.
4. `recordResourceUsage()` takes the `decisionId` of the allowed decision and
   the request's `startedAt`, and no longer takes `subjectId` or `clientId`.
5. Resource webhooks are a union: handle `resource.grant.updated` (new level in
   `grant.permission`, former one in `grant.previousPermission`) and
   `resource.deleted` (resource only, no `grant` or `recipients`).
6. Grants use `read` and `write`; the former `use` value is gone. A resource
   deletion is permanent and returns the deleted `Resource`.
7. `AccessibleResource.permission` is always present and `ownerId` is optional.

## New

- `createResourceSharingClient()` returns the signed-in user's grant client
  (`createGrant`, `updateGrant`, `revokeGrant`, `deleteGrant`,
  `shareWithApplication`) from a verified token carrying `resources:self:manage`.
- `RESOURCE_PERMISSIONS`, `ResourcePermission`, `ResourceSharingClient`, the grant
  input types, `ResourceGrantEvent` and `ResourceDeletedEvent` are re-exported.
