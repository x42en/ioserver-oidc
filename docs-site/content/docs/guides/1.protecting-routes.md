# Protecting Routes and Namespaces

## Selective controller protection

Middleware applies at controller level. Register separate controllers for public
and protected routes:

```ts
server.addController({ name: "public", controller: PublicController });

server.addController({
  name: "api",
  controller: ApiController,
  middlewares: [OidcHttpMiddleware],
});
```

## Mixed-access namespaces

```ts
server.addService({ name: "announcements", service: AnnouncementService });

server.addService({
  name: "app",
  service: AppService,
  middlewares: [OidcSocketMiddleware],
});

server.addService({
  name: "panel",
  service: AdminPanelService,
  middlewares: [OidcSocketMiddleware, OidcSocketAdminMiddleware],
});
```

## Checking permissions and features

Use the re-exported auth-ai helpers so the write-implies-read rule stays
consistent with auth-service:

```ts
import { hasFeature, hasPermission, hasRole } from "ioserver-oidc";

class ProjectController extends BaseController {
  async deleteProject(request: any, reply: any) {
    if (!hasPermission(request.auth, "projects", "write")) {
      return reply.code(403).send({ error: "ERR_FORBIDDEN" });
    }
    reply.code(204).send();
  }

  async export(request: any, reply: any) {
    if (!hasFeature(request.auth, "exportEnabled")) {
      return reply.code(403).send({ error: "Feature not included" });
    }
    reply.send({ ok: true });
  }
}
```

The browser is not a security boundary: enforce every entitlement on the server.

## Machine tokens

In native mode, `client_credentials` tokens are refused by default with
`ERR_MACHINE_TOKEN_FORBIDDEN`. If a route is genuinely machine-facing, enable
them explicitly and keep them on a separate controller:

```env
AUTH_SERVICE_ALLOW_MACHINE_TOKENS=true
```

A machine token has no user: do not call `findOrCreate` for it in your own code
and do not treat it as an end user.

## Accessing the config from handlers

```ts
import { OidcConfigManager } from "ioserver-oidc";

class DebugController extends BaseController {
  async oidcConfig(request: any, reply: any) {
    const mgr = this.app.getManager("oidcConfig") as OidcConfigManager;
    const config = mgr.getConfig();
    reply.send({ provider: config.provider, issuer: config.issuer });
  }
}
```

## Forwarding auth context

When calling another internal service, forward the original bearer token. The
downstream service verifies it independently:

```ts
const result = await fetch("http://internal-service/data", {
  headers: { Authorization: request.headers.authorization },
});
```

Never forward the raw token to an unrelated origin, and never log it.
