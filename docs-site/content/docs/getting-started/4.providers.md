# Providers

`ioserver-oidc` has two providers. Both use the same middlewares and produce the
same `OidcUserContext`; only token validation and claim names differ.

## `auth-service` (default)

`OIDC_PROVIDER` is unset or set to `auth-service`.

| Variable                            | Required | Default                            | Description                                                    |
| ----------------------------------- | -------- | ---------------------------------- | -------------------------------------------------------------- |
| `AUTH_SERVICE_URL`                  | Yes      | —                                  | Public base URL of auth-service.                               |
| `AUTH_SERVICE_APP_SLUG`             | Yes      | —                                  | OAuth2 `client_id` / application slug.                         |
| `AUTH_SERVICE_AUDIENCE`             | No       | `AUTH_SERVICE_APP_SLUG`            | Expected `aud` (RFC 8707 resource URL).                        |
| `AUTH_SERVICE_JWKS_URI`             | No       | `<AUTH_SERVICE_URL>/api/auth/jwks` | JWKS endpoint override.                                        |
| `AUTH_SERVICE_ISSUER`               | No       | `AUTH_SERVICE_URL`                 | Issuer override.                                               |
| `AUTH_SERVICE_GATEWAY_URL`          | No       | —                                  | LiteLLM gateway URL for `createRequestGatewayClient()`.        |
| `AUTH_SERVICE_CLIENT_SECRET`        | No       | —                                  | Confidential secret for `OidcMachineManager`.                  |
| `OIDC_RESOURCE_METADATA_URL`        | No       | —                                  | RFC 9728 metadata URL used in the Bearer challenge.            |
| `OIDC_SCOPES_SUPPORTED`             | No       | —                                  | Comma-separated scopes advertised in metadata.                 |
| `AUTH_SERVICE_ALLOW_MACHINE_TOKENS` | No       | `false`                            | Accept `client_credentials` tokens on user routes.             |
| `AUTH_SERVICE_ADMIN_ROLES`          | No       | `admin`                            | Comma-separated roles accepted by the admin socket guard.      |
| `AUTH_SERVICE_TOKEN_TYP`            | No       | —                                  | Required JOSE `typ` header for access tokens.                  |
| `OIDC_ALLOW_INSECURE_HTTP`          | No       | `false`                            | Allow plain HTTP to non-loopback services.                     |

The native verifier maps the auth-service claims directly:

| Context field  | Claim           |
| -------------- | --------------- |
| `roles`        | `roles`         |
| `permissions`  | `permissions`   |
| `features`     | `features`      |
| `plan`         | `plan`          |
| `org_id`       | `org_id`        |
| `sid`          | `sid`           |
| `scopes`       | `scope`         |
| `clientId`     | `azp` / `client_id` |
| `email`        | `email`         |
| `name`         | `name`          |
| `picture`      | `picture`       |
| `company`      | `company`       |

A `client_credentials` token has `sub === azp`. It is refused by default with
`ERR_MACHINE_TOKEN_FORBIDDEN`; set `AUTH_SERVICE_ALLOW_MACHINE_TOKENS=true` only
when your routes are meant to accept machine callers.

## `oidc` (generic provider)

```env
OIDC_PROVIDER=oidc
OIDC_ISSUER=https://login.example.com
OIDC_JWKS_URI=https://login.example.com/.well-known/jwks.json
OIDC_AUDIENCE=api://my-api
OIDC_CLIENT_ID=my-client
```

| Variable                       | Required | Default               | Description                                   |
| ------------------------------ | -------- | --------------------- | --------------------------------------------- |
| `OIDC_ISSUER`                  | Yes      | —                     | Token issuer.                                 |
| `OIDC_JWKS_URI`                | Yes      | —                     | JWKS endpoint.                                |
| `OIDC_AUDIENCE`                | Yes      | —                     | Expected `aud`.                               |
| `OIDC_CLIENT_ID`               | Yes      | —                     | Client id used for authorized-party binding.  |
| `OIDC_ALGORITHMS`              | No       | asymmetric allow-list | Comma-separated asymmetric JWS algorithms; `HS*`/`none` rejected. |
| `OIDC_ALLOW_MACHINE_TOKENS`    | No       | `false`               | Accept tokens without an end user.            |
| `OIDC_ADMIN_ROLES`             | No       | `admin`               | Admin roles for the socket guard.             |
| `OIDC_CLOCK_TOLERANCE_SECONDS` | No       | `5`                   | Accepted clock skew (0–300).                  |
| `OIDC_TOKEN_TYP`               | No       | —                     | Required JOSE `typ` header for access tokens. |
| `OIDC_ALLOW_INSECURE_HTTP`     | No       | `false`               | Allow plain HTTP to non-loopback services.    |
| `OIDC_RESOURCE_METADATA_URL`   | No       | —                     | RFC 9728 metadata URL for Bearer challenges.  |
| `OIDC_SCOPES_SUPPORTED`        | No       | —                     | Comma-separated scopes advertised in metadata.|

### Claim mapping

Providers that use other claim names can map them:

| Variable                         | Default              |
| -------------------------------- | -------------------- |
| `OIDC_ROLES_CLAIM`               | `roles`              |
| `OIDC_PERMISSIONS_CLAIM`         | `permissions`        |
| `OIDC_FEATURES_CLAIM`            | `features`           |
| `OIDC_PLAN_CLAIM`                | `plan`               |
| `OIDC_ORG_ID_CLAIM`              | `org_id`             |
| `OIDC_EMAIL_CLAIM`               | `email`              |
| `OIDC_NAME_CLAIM`                | `name`               |
| `OIDC_PICTURE_CLAIM`             | `picture`            |
| `OIDC_COMPANY_CLAIM`             | `company`            |
| `OIDC_AUTHORIZED_PARTY_CLAIMS`   | `azp,client_id`      |

Example for an Entra ID-style token:

```env
OIDC_ROLES_CLAIM=roles
OIDC_PERMISSIONS_CLAIM=scp
OIDC_AUTHORIZED_PARTY_CLAIMS=azp,appid
OIDC_ORG_ID_CLAIM=tid
```

As with the native provider, only asymmetric algorithms are accepted and `iss`
plus `aud` are always validated. When `OIDC_CLIENT_ID` is set, the authorized
party must match it.
