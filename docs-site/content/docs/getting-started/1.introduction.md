# Introduction

`ioserver-oidc` adds JWT authentication to [IOServer](https://docs.circle-cyber.com/ioserver/)
applications. It provides middleware classes that slot into IOServer's existing
middleware arrays and protect both Fastify controllers and Socket.IO services.

Native support for [CIRCLE auth-service](https://docs.circle-cyber.com/auth-service/)
is the default. Any other standards-compliant OAuth 2.x / OIDC issuer remains
supported through the generic `oidc` provider.

## IOServer primer

Every `addController` and `addService` call accepts a `middlewares` array.
Middlewares run before each HTTP handler or WebSocket handshake:

```ts
import { IOServer } from "ioserver";
import { OidcHttpMiddleware, OidcSocketMiddleware } from "ioserver-oidc";

const server = new IOServer({ port: 3000 });

server.addController({
  name: "api",
  controller: ApiController,
  middlewares: [OidcHttpMiddleware],
});

server.addService({
  name: "chat",
  service: ChatService,
  middlewares: [OidcSocketMiddleware],
});

await server.start();
```

## What the package provides

| Export                           | Type             | Role                                                        |
| -------------------------------- | ---------------- | ----------------------------------------------------------- |
| `OidcConfigManager`              | `BaseManager`    | Reads and validates the environment                         |
| `OidcHttpMiddleware`             | `BaseMiddleware` | Verifies bearer tokens on HTTP routes                       |
| `OidcSocketMiddleware`           | `BaseMiddleware` | Verifies tokens on Socket.IO handshakes                     |
| `OidcSocketAdminMiddleware`      | `BaseMiddleware` | Role guard for privileged namespaces                        |
| `verifyOidcToken`                | function         | Low-level token verification                                |
| `createGatewayClient`            | function         | LiteLLM gateway client from a user token                    |
| `createRequestGatewayClient`     | function         | Gateway client from `request.authToken`                     |
| `createWalletClient`             | function         | auth-service credit wallet reads                            |
| `registerBackchannelLogout`      | function         | Mounts the OIDC Back-Channel Logout endpoint                |
| `OidcMachineManager`             | `BaseManager`    | auth-service machine API and resource sharing               |
| `requireResourceAccess`          | function         | Fail-closed resource admission                              |
| `registerResourceWebhook`        | function         | Verifies signed resource-sharing webhooks                   |
| `registerProtectedResourceMetadata` | function      | Serves RFC 9728 metadata                                    |
| `hasRole`, `hasPermission`, …    | functions        | Entitlement helpers shared with `@circle-rd/auth-ai`        |

## Authentication flow

```text
Client                   IOServer                  auth-service
  │                         │                           │
  │ POST /api/resource       │                           │
  │ Authorization: Bearer …  │                           │
  │────────────────────────►│                           │
  │                         │ OidcHttpMiddleware         │
  │                         │  verifyOidcToken()         │
  │                         │   getJwks(jwksUri) ───────► GET /api/auth/jwks
  │                         │   jwtVerify(token, keyset)  ◄──── { keys: [...] }
  │                         │  → OidcUserContext         │
  │                         │  users.findOrCreate(sub)   │
  │                         │ handler(request, reply)    │
  │ 200 OK                  │                           │
  │◄────────────────────────│                           │
```

JWKS keys are cached in-process per URI. `jose` refreshes them on an unknown
key, so normal traffic does not repeatedly hit auth-service.

## Native auth-service contract

The default provider expects:

- `iss` — `AUTH_SERVICE_URL` (or `AUTH_SERVICE_ISSUER`).
- `aud` — the RFC 8707 resource URL (`AUTH_SERVICE_AUDIENCE`). Legacy
  deployments may omit it and fall back to `AUTH_SERVICE_APP_SLUG`.
- `azp` / `client_id` — bound to `AUTH_SERVICE_APP_SLUG`.
- `sub` — stable user identifier.
- Optional claims: `roles`, `permissions`, `features`, `plan`, `org_id`, `scope`
  and `sid`.
- JWKS at `<AUTH_SERVICE_URL>/api/auth/jwks` (or `AUTH_SERVICE_JWKS_URI`).

`client_credentials` tokens (`sub === azp`) are rejected by default because they
have no end user to provision.

## Other OIDC providers

Set `OIDC_PROVIDER=oidc` to use any issuer that publishes a JWKS. The generic
provider supports configurable claim names and authorized-party claims; see
[Providers](/docs/getting-started/providers).
